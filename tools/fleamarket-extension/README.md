# フリマ購入履歴の自動取得

登録済みの7アカウント（メルカリ2、ヤフオク2、Yahoo!フリマ2、ラクマ1）で、毎日01:00 JSTに購入・落札履歴を取得して管理アプリの在庫一覧内「仕入れリスト」に下書きを保存します。

- 保存名とサイトのログイン名の一致を確認。ログイン切れ・追加認証・名前不一致ではそのアカウントを停止し確認タスクを残します。
- サーバーの日本時間を基準に直近2週間（14日前以降）の購入だけを対象にし、完了済みを含め、キャンセル済みを除外します。
- 在庫にある商品は追加しません。在庫登録済みが5件連続した場合は、そのアカウントの取得を終了します。除外済み・反映済み・取り込み済みの全下書きは再追加しません。
- 購入日・商品名が確認できなければタスクにして保存を見送ります。金額は詳細でも確認できなければnull。一度取り込んだ商品は再取得しません。
- 商品名、商品ID、正規の商品URL、購入日、金額、サイト、アカウントを保存。既存の商品マスターで型番が1つに特定できる場合は既存関数で紐付けます。
- 「在庫一覧へ反映」は既存の利用者操作です。自動取得は購入・入札・メッセージ・評価送信を行いません。

同じサイトへの購入取得と追跡巡回は、管理者専用の2分期限付き取得権限で順番に進めます。権限はアカウント終了・停止で解除し、Chrome停止時も期限で復帰します。長いDBトランザクションをブラウザー操作中に保持しません。

通常の定期実行は purchases → tracking の順。受け取り評価と旧Codex ID1/2は停止を維持します。Chromeを後から起動した場合は、その日に未実行の処理を追いついて実行します。手動実行は日次実行の記録を消しません。

通信エラーの再試行は、新しい購入用RPC3つだけに限定します。評価・メッセージ送信を自動再送しません。認証情報はtrusted contextのみ、公開キー以外をソースへ入れません。
