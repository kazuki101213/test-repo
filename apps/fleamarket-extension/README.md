# フリマ取引サポート v0.1.6

Chrome Manifest V3拡張機能の初期実装です。最初は「診断のみ」で動作し、在庫更新・評価送信はしません。

## 最初にする操作

1. `start-install.cmd`をダブルクリックします。Chromeの拡張機能画面でデベロッパーモードをオンにし、「パッケージ化されていない拡張機能を読み込む」からこのフォルダーを選択します。フォルダーのパスはコピーされます。
2. 拡張機能を固定し、「管理アプリと連携」を押します。管理アプリが未ログインなら初回だけ管理者でログインし、再度連携します。通常の巡回時には管理画面へのログインは不要です。
3. 各サイトの購入一覧を開き、拡張機能のアイコンから対象アカウントを選び、「①自分の名前を紐付ける」でサイト上の自分のログイン表示をクリックします。続けて「②現在の購入一覧を登録」を押します。

同じサイトの2アカウントは別Chromeプロファイルに登録します。使用するプロファイルごとに同じフォルダーの拡張機能を追加してください。Chromeのログイン・認証コード入力は利用者が手動で行います。

## 実画面の確認

「追跡番号を確認」で更新を伴わない照合を実行できます。1回の処理で一覧または取引1件を確認し、通常1分ごとに続きを進めます。設定画面に進捗と記録を表示します。

購入一覧と取引画面で「現在の画面の診断を保存」を押すと、Downloadsに`fleamarket-page-diagnostic.json`が保存されます。設定画面の「設定・診断記録を保存」でも診断を保存できます。このチャットからTailscale経由でそのファイルを取得し、サイトごとの設定を調整できます。利用者がSQLやコードを書く必要はありません。

現時点では各サイトのログイン後のDOMを実地検証していません。商品ID・購入者側・未完了・アカウントを確定できない画面では停止します。取引画面にアカウント名が表示されない場合、サイト専用の追加調整が必要です。

## 購入履歴から仕入れリストを作成

メルカリ、ヤフオク、Yahoo!フリマ、ラクマのログイン済み購入一覧を登録した後、小窓の「購入履歴を同期」を押します。拡張機能は登録済み一覧のページを巡回し、商品ID・商品名を確認できた履歴をSupabaseの仕入れリストへ保存します。同じサイトの商品IDは一度だけ下書きになり、在庫に登録済みの商品は新しい下書きにしません。

管理アプリの「在庫一覧」上部にある「仕入れリスト」で内容を確認し、「在庫一覧へ反映」を押します。購入日や金額を取得できなかった履歴は空欄のまま開くため、登録前に入力してください。拡張機能は在庫を直接作成せず、確認後の在庫登録フォームから反映します。反映済みの下書きは再登録できません。「除外」は誤検出した履歴をリストから隠します。

購入一覧のDOMはサイト更新で変わる場合があります。4サイトの実アカウント画面で取得結果を確認するまでは、同期後に商品ID・商品名・購入日・金額を目視で照合してください。

受け取り評価のエンジンは、検証済みの単一評価フォームに対応しています。評価画面への移動、複数段階の確認、サイト固有の選択要素は、実画面診断後に調整します。初期版のまま全サイトで評価が送信できるとは確認していません。

## 本番への切り替え

このチャットで実画面の照合を確認し、サイトごとの画面設定を検証済みにした後、追跡番号登録を有効にします。受け取り評価の実行には在庫1件一致、検品・清掃の両方の記録、検証済み評価フォームが必要です。

既存Codex処理との重複を解消した後に、受け取り評価を含むモードに切り替えます。初期版の導入で既存Codex自動処理は停止しません。

## 保存・権限・実行条件

- 購入履歴は日本時間の午前3時に毎日自動同期します。各登録アカウントの最新一覧ページだけを確認し、古いページは開きません。過去分が必要な場合は「購入履歴を同期」から手動で取得します。
- 自動同期はChromeのalarmsを使い、Chromeと対象プロファイル、PCが動作している必要があります。停止・スリープ中の実行は保証できません。起動・復帰後12時間以内なら未実行分を確認します。
- サイト側のボット対策を回避する動作は行いません。自動処理は1日1回に限定し、登録済みアカウントの購入一覧だけを読み取ります。
- 追跡番号の照合・受け取り評価は引き続き設定時刻（初期値は日本時間の午前1時・午前2時）にChrome alarmsで巡回します。Windowsタスクスケジューラーは使用しません。
- Supabaseへの接続には公開キーと管理者の独立したログインセッションを使います。service_roleなどの秘密キーは含みません。
- 初回連携では、ログイン済み管理アプリの権限を検証し、既存のアプリ用ログイン処理で拡張機能専用のセッションを作成します。元の管理アプリのrefresh tokenは共有しません。認証情報は拡張機能のローカル保存に限定し、サイト側スクリプトや診断ファイルには公開しません。
- 在庫登録・確認タスクは既存の`app.reconcile_marketplace_tracking`だけで処理します。クライアントからテーブルへ直接INSERT/UPDATEしません。
- `app.marketplace_extension_probe`は在庫照合用、`app.marketplace_extension_receipt`は評価予約・送信状態記録用です。両方とも管理者認証を要求し、SECURITY INVOKERで動作します。
- 追跡番号は空欄への登録だけです。Yahoo!フリマの「ヤフフリ」「PayPayフリマ」をまとめて在庫の件数を判定します。
- 評価送信は良い評価、任意コメントなし、必須コメントだけ「ありがとうございました。」です。
- 評価予約をSupabase側に保存し、別Chromeプロファイル間の二重予約を防止します。送信結果が不明な場合は再送せず確認タスクに記録します。未確認の予約は自動解除しません。
- 発送、購入、入札、キャンセルを自動で行うコードは実装していません。仕入れリストへの登録はログイン中の購入一覧から読み取った情報だけを使います。
- ダッシュボードへのタスク送信に失敗した場合は、拡張機能内に未送信として保存して接続復旧後に再送します。
- ブラウザーのデータ消去、拡張機能の削除でローカル設定・未送信記録は失われます。Supabase側の評価記録は保持されます。

購入履歴 /buy には名前が表示されずmain要素もない診断結果を確認した。固有の「購入した商品」見出しを範囲とし、/transaction?item_id= の32文字の商品IDを厳密に読み取る。
ラクマは https://fril.jp/mypage で「名前さんのマイページ」を①で選択後、購入した商品へ移動して②を押す。購入履歴・取引・評価前の各読み取りでは、別の非アクティブな確認タブで登録マイページの名前を再確認する。確認タブは閉じ、ユーザーの既存タブは移動しない。名前・認証・確認URLに問題があれば処理を停止する。一時的な確認済みフラグは設定へ保存不可。

## 0.1.1 ラクマの自動登録
ラクマのログイン済みマイページか購入一覧で「ラクマを自動登録」を押すだけで、非アクティブタブのマイページから唯一の「名前さんのマイページ」を取得し、購入一覧を確認して登録する。①②の操作は不要。認証切れ、複数の名前、対象ページの不一致では登録しない。登録成功やエラーは小窓上部に表示する。手動登録の選択アカウントが再描画で先頭へ戻る不具合も修正。
27件のテストを確認（選択肢の表示待ち条件を修正したUIテスト1件は再実行して通過）。実サイトでの自動登録完了はまだ未確認。配置先は更新前と同じで、Chromeの拡張機能カードの再読み込み後にバージョン0.1.1を確認する。


## 0.1.2 名前・購入一覧の登録削除
小窓の「選択アカウントの登録を削除」、または設定の各アカウント行の「登録を削除」で、選択した登録だけを未登録に戻す。名前のみ登録された段階でも削除できる。巡回中は停止後に操作する。他のアカウント、管理アプリの連携、在庫や評価記録は削除しない。


## 0.1.3 共通の自動登録ボタン
メルカリ・Yahoo!フリマ（旧PayPayフリマ）・ラクマを「このサイトを自動登録」に統一。対象アカウントの1または2を選んで押す。選択アカウントと開いているサイトが違う場合は登録しない。メルカリは /mypage/purchases、Yahoo!フリマは /my または /mypage 配下の購入一覧で、ヘッダーのアカウント名候補が唯一の場合だけ取得する。出品者名や商品本文から名前を推測しない。ラクマは従来のマイページ確認に委譲する。各処理前の別ページのアカウント再確認と登録削除ボタンを維持。
名前の候補を限定できない画面では自動登録しない。画面診断JSONは限定した名前候補と要素位置を含む。認証情報は含めない。31件のテスト通過。実サイトのメルカリ・Yahoo!フリマでの自動登録成功は未確認。診断モードと既存Codex自動処理を維持。
