# 出品者側の購入者評価

既存 `sellerDaily` の日次販売確認で取得した行だけを再利用し、専用巡回やアラームを増やさない。4時間ごとの確認では評価を行わない。

- 対象は有効な mercari-1/2、auctions-1/2。既存セッションで本人名を確認し、新しいタブを開かない。
- メルカリは評価待ちの行。ヤフオクは評価待ち・チャージ完了の候補から、実リンク経由の出品者取引ナビで受取完了を必ず再確認する。
- `seller_feedback_candidates` で在庫・販売サイト・アカウント・取引キー・未解決操作をまとめて照合する。
- `seller_feedback_record` の reserve → begin → complete を使う。channel+external_idを一意とし、reserved/submitting/unknownは自動再送しない。
- メルカリは良かった、ヤフオクは非常に良い。任意コメントは空欄、必須のみ固定のお礼。入力済みのコメントや悪い評価を自動で上書きしない。
- メルカリの「購入者を評価して取引完了する」は確認ダイアログを開く操作。実文言「購入者を評価して取引を完了しますか？」と「取引を完了する」を照合して最終確認する。同時表示の別ダイアログは操作しない。
- ヤフオクはisSeller、新規評価、商品ID、公開先、評価内容を確認し、公開後GETの前回評価・時刻・文面で成功を確認する。
- 不明結果は記録と実画面の読取で確認する。DB予約を自動解除しない。review RPCは元の管理者の結果確認用で、送信状態をリセットしない。

拡張側の恒久設定は `production-plan.js` の `sellerFeedbackSites`。稼働中の設定は `sellerFeedbackPolicy` としてtrusted storageへ保存し、ポップアップの状態で表示する。認証情報を含めない。

1645aの一度限りの追加操作コードは最終版から削除。購入者側受取評価の設定・既存出品機能は変更しない。
