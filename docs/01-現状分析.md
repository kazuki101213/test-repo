# 01 現状分析

いただいた 2 つのスプレッドシートを読んで、移行にあたって判断したことをまとめます。

## 総合管理表

| シート | 内容 | 移行先 |
|---|---|---|
| KPI 集計 | 売上高・純利益・総仕入れ数・現在庫数・回転率など | `app.v_monthly_summary` / `app.v_stock_summary` |
| 商品リスト（628 件） | 商品番号・ASIN・型番・メーカー・非常に良い販売・振込額・仕入れ目標・回転・月間仕入れ可個数 | `app.products` |
| 経費 | 固定費・変動費・給与・支払スケジュール | `app.expenses` |
| クレカ管理 | カード名・下四桁・限度額・締め日・引き落とし日 | `app.payment_cards` |
| 自動仕入れツール設定 | キーワード・価格帯・自動購入フラグ | **移行しない**（別ツールの設定なのでシートのままでよい） |
| 利益ピボット（販売日 × 仕入担当者） | 担当者別の利益集計 | `app.v_items` から都度集計 |
| ヤフオク/PayPay 購入メール抽出 | GAS でメールから購入履歴を取り込み | 仕入登録の下書きとして残せる（後述） |

## 納品管理表

納品担当者ごとに同じ列構成のシートが 9 枚あり、そこに「出品テンプレート」
「コンディション変換表」「担当者別集計」が加わっています。

担当者シートの列はすべて `app.items` の 1 行に収まります。

```
出品者SKU / 仕入担当者 / 納品担当者 / 購入日 / 商品名 / 仕入金額 / ID / 追跡番号 /
通番号 / 品番 / ASIN / 販売予定価格 / 振込予定額 / 仕入れ先 / 状態 / 販売先 /
クレカ / 商品URL / 説明文 / 双方向コメント / 商品登録・撮影 / 検品・清掃 /
写真登録 / 梱包日 / 出荷日
```

## 移行時に判断したこと

### 1. 「状態」列が 2 つの意味を持っていた

`非常に良い` `ほぼ新品` `可` といったコンディションと、`返品処理` という進行状態が
同じ列に入っていました。集計時にどちらの意味で数えるかが毎回曖昧になるため、
**`condition`（品質）と `status`（進行状態）に分けています。**

`返品処理` の行は `status = '返品'` + `returned_on` に移し、
コンディションは空にしています（元の品質が分かる行は手で入れ直せます）。

### 2. 担当者名の接頭辞は「人」ではなく「作業ライン」だった

`(テ)株式会社コエル` と `(ブ)株式会社コエル` は同じ会社です。
`(テ)=テレビ` `(ブ)=ブルーレイ` `(付)=付属品` という作業の区分でした。

人の名前に区分を混ぜると担当者別の集計がずれるので、
**`work_stream` 列として切り出し、`staff` は会社名だけ**にしています。

`(石)長部一輝` の `(石)` は石川さん案件を長部さんが代行した印のようでしたが、
作業ラインではないので取り込み時に捨てています。必要なら列を足せます。

### 3. 通番号は「ロット」だった

`2340-EEMM-20260916-1296`（本体）と `2340-AAMM-20260924-173`（リモコン）のように、
本体と後から買い足した付属品が同じ通番号を共有していました。

`app.lots` として独立させ、`is_accessory` で本体と付属品を区別しています。
これで「この本体の原価は、付属品を含めていくらか」が SQL 一本で出せます。

### 4. 販売予定価格が空 or ¥0 の行は付属品

移行スクリプトはこの規則で `is_accessory` を自動判定します。
例外があれば取り込み後に大元アプリで直せます。

### 5. 日付の表記ゆれ

梱包日・出荷日には `2025/9/25` と `9/25` と `-` が混在していました。
年が省略されている場合は**購入日の年**で補完しています。
年をまたぐ仕入れ（12 月購入 → 1 月出荷）は取り込み後に確認してください。

### 6. ASIN に制御文字が混ざっていた

`&#9;B07ZDDDW1G` のようにタブの実体参照が付いた行があります。
取り込み時に 10 桁の英数字だけを抜き出しています。

## いま困っていそうなことと、その解決

| 今の困りごと | この仕組みでどうなるか |
|---|---|
| 担当者を増やすたびにシートを増やして数式を直している | 担当者を `staff` に 1 行足すだけ。画面は共通 |
| 外注先に他の人の仕入金額や利益が見えてしまう | RLS で行ごと遮断。納品アプリには金額列を出していない |
| コピペで SKU がずれる | 仕入登録時に DB が発番。手入力の余地なし |
| 集計シートが重い / 壊れる | 集計はビューで都度計算 |
| 古物台帳の記載漏れに気づけない | 1 万円以上で相手方未記入の行を古物台帳画面が警告する |
| 誰がいつ何を直したか分からない | `app.audit_log` に全変更が残る |
