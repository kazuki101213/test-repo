# 商品リストの価格巡回（price-patrol）

2026-11-29 ユーザー指定。商品リストの販売想定金額を、3日に1回、今の相場に合わせる。

## 決まり

| 商品 | 相場の取り方 |
|---|---|
| 実績あり（`has_sold_before = true`） | Amazon SP-API（価格API `getItemOffers`、中古）で、今出ている「非常に良い」かつFBAの出品の最安値（本体＋送料） |
| 実績無し | Keepaのオファー（`offers=20`、過去の出品を含む）から、Prime・ほぼ新品／非常に良い／良い・最終確認60日以内の出品を、最終確認が新しい順に5件とって、その値段（本体＋送料）の中央値 |

- 相場が今の価格から **25%以内** なら、上げ下げとも販売想定金額を書き換える。25%を超えるとき・相場が無いときは変えない。
- 書き換えたら、振込想定金額（販売価格 − Amazon手数料（FBA）− 500円）を手数料APIで出し直す。仕入れ目標金額は、今の値が決まり（利益率）どおりなら計算し直し、手で入れた値なら残す（毎日の振込照合と同じ）。
- 手数料の見積もりが返らないときは書き換えない。

## 動き方

- pg_cron `price-patrol` が5分ごとに Edge Function `price-patrol` を呼ぶ（認証は `x-amazon-cron-token`）。
- 1回で、実績ありを最大20件（バッチ1回）と、実績無しをKeepaのトークンが続く限り数件進める。
- 各商品は前回から3日たつと、また対象になる（`app.price_patrol_due`）。
- KeepaのAPIキーは Vault の `keepa_api_key`。プランは毎分1トークン回復で、1商品7〜14トークン。実績無し約270件は約2日で一巡する。

## 記録

- `app.price_patrol_checks`：商品ごとの最後の確認（相場・結果・理由）
- `app.price_patrol_changes`：書き換えた履歴（前後の販売想定・振込想定・仕入れ目標）

## 止めるとき

```sql
select cron.unschedule('price-patrol');
```
