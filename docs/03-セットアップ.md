# 03 セットアップ

## 1. Supabase プロジェクトを作る

1. https://supabase.com でプロジェクトを作成（リージョンは `Northeast Asia (Tokyo)`）
2. `Project Settings → API` から **Project URL** と **anon public key** を控える
3. **service_role key** も控える（移行スクリプト専用。アプリには絶対に入れない）

## 2. スキーマを流す

### 方法A: ダッシュボードに貼り付ける（インストール不要・おすすめ）

1. 左メニューの **SQL Editor** を開く
2. [`supabase/setup-all.sql`](../supabase/setup-all.sql) の中身を全部コピーして貼り付ける
3. **Run** を押す

`setup-all.sql` は `supabase/migrations/*.sql` を連結した自動生成ファイルです。
マイグレーションを足したら `scripts/build-sql-bundle.sh` で作り直してください
（ずれていれば CI が落ちます）。

### 方法B: Supabase CLI を使う

継続的に開発するならこちらです。

```bash
npm i -g supabase
supabase login
supabase link --project-ref <your-project-ref>
supabase db push
```

`supabase/config.toml` で `app` スキーマを API に公開しています。
ダッシュボードから設定した場合は `Settings → API → Exposed schemas` に
`app` が入っているか確認してください。

## 3. スタッフとログインアカウントを作る

`20260920000500_seed_master.sql` が担当者とカードを登録済みです。
**担当者コードは既存 SKU と対応しているので変更しないでください。**

| コード | 氏名 | 役割 |
|---|---|---|
| AA | 長部一輝 | admin |
| EE | 石川秀樹 | purchaser |
| DD / HH / II / JJ / GG / LL | 久保田ゆかり / 新川水紀 / 久保田真由 / 神谷愛 / 和田知佳 / 土井花菜 | deliverer |
| FF / KK / MM | 株式会社グレイス / コエル / 吉光 | deliverer（外注） |

次に、Supabase の `Authentication → Users → Add user` で各人のアカウントを作り、
`app.profiles` で `staff` と紐付けます。

```sql
insert into app.profiles (user_id, staff_id)
select u.id, s.id
from auth.users u, app.staff s
where u.email = 'kubota@example.com' and s.code = 'DD';
```

紐付いていないアカウントはログインしてもエラーになります（意図的な作りです）。

新しい担当者を増やすときは、**まだ使われていない 2 文字コード**を割り当ててください。

```sql
insert into app.staff (code, name, role) values ('NN', '新しい人', 'deliverer');
```

## 4. アプリを動かす

```bash
pnpm install

cp .env.example apps/admin/.env.local
cp .env.example apps/delivery/.env.local
# それぞれ VITE_SUPABASE_URL と VITE_SUPABASE_ANON_KEY を書き込む

pnpm dev:admin      # 大元アプリ    http://localhost:5173
pnpm dev:delivery   # 納品アプリ    http://localhost:5174
```

## 5. デプロイ

どちらも静的サイトなので、Vercel / Netlify / Cloudflare Pages のいずれでも動きます。
**2 つを別のドメインに置いてください。** URL が分かれていれば、
外注先に納品アプリの URL だけを渡せます。

```
# Vercel の例（プロジェクトを 2 つ作る）
Root Directory : apps/admin        Build: pnpm build   Output: dist
Root Directory : apps/delivery     Build: pnpm build   Output: dist
```

環境変数（`VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`）は各プロジェクトに設定します。
anon key は公開されても問題ありません。データを守っているのは RLS です。

納品アプリはスマホのホーム画面に追加して使う想定で、
タップ領域と文字サイズを現場向けに調整してあります。

## 6. 動作確認

```bash
sudo service postgresql start
supabase/tests/run.sh
```

ローカルの PostgreSQL にマイグレーションを流し、次を検証します。

- SKU が規則どおり発番されるか
- 納品担当者に他人の商品が見えないか
- 納品担当者が仕入金額を書き換えられないか
- 古物台帳・月次集計が正しく出るか
