# 05 古物台帳

スプレッドシートが古物台帳を兼ねていたので、その役割はこのシステムが引き継ぎます。
`app.v_antique_ledger` が台帳で、大元アプリの「古物台帳」画面から CSV 出力できます。

> ここに書いているのは、いただいたシートの内容と法令の記載事項を突き合わせた整理です。
> 実際の運用可否は、許可を受けた公安委員会（所轄の警察署 生活安全課）にご確認ください。

## 記載事項との対応

古物営業法施行規則 第16条が求める項目と、このシステムの列の対応です。

| 法令上の記載事項 | 対応する列 | 状態 |
|---|---|---|
| 取引の年月日 | `purchased_at` / `sold_on` | ✅ 自動 |
| 古物の品目 | `products.genre`（未設定は「家電・事務機器類」） | ✅ 自動 |
| 古物の特徴 | 商品名 + 型番 + ASIN + コンディション | ✅ 自動 |
| 数量 | 個体ごとに 1 行なので常に 1 | ✅ 自動 |
| 代価 | `cost_amount` / `sold_price` | ✅ 自動 |
| 相手方の住所・氏名・職業・年齢 | `seller_address` / `seller_name` / `seller_occupation` / `seller_age` | ⚠️ **未入力** |
| 相手方の確認方法 | `identity_check` | ⚠️ 自動判定（下記） |

## 確認しておいたほうがよい点

**現在のシートには、仕入れ相手の氏名・住所が記録されていません。**
残っているのはメルカリ/ヤフオクの取引 ID と商品 URL だけです。

法令の建て付けはこうなっています。

- 1 万円未満の買受は帳簿の記載義務が免除されます
  （ただし**ゲームソフト・CD/DVD・書籍・自動二輪車およびその部品は金額にかかわらず記載が必要**）。
- 1 万円以上の買受では、相手方の確認（本人確認）と帳簿への記載が必要です。
- 非対面（通信販売）の取引には、古物営業法施行規則 第15条に定められた
  確認方法があり、プラットフォームの取引記録だけで足りるかは方法によって変わります。

いただいたデータを見ると、**1 万円以上の仕入れが多数あります**
（例: ¥12,961 / ¥16,140 / ¥31,700 など）。
この部分は現状のシートでも記載が足りていない可能性が高く、
システムに移しても自動では埋まりません。

そこで次のようにしています。

1. `identity_check` を仕入金額から自動判定する
   - 1 万円未満 → `確認不要(1万円未満)`
   - 1 万円以上 → `非対面(取引記録)`（取引 ID と URL を証跡として残す）
2. 大元アプリの古物台帳画面で、
   **1 万円以上なのに相手方の住所が空の行を数えて警告**する
3. 仕入登録フォームに `seller_*` を入力できるようにしてある

警察に確認したうえで、取引記録だけで足りるなら警告は無視して構いませんし、
氏名・住所の取得が必要なら、メルカリ/ヤフオクの取引画面から
発送元情報を `seller_name` / `seller_address` に入れる運用にできます。

## 保存期間

帳簿は**最後に記載した日から 3 年間**保存する必要があります。

- `app.items` の行は削除せず、`status = '廃棄'` で論理削除してください
  （物理削除は管理者のみ可能にしてあります）
- すべての変更は `app.audit_log` に変更前後の JSON ごと残ります
- 定期的に古物台帳 CSV を書き出して保管しておくと安心です

```sql
-- 年に 1 回、前年分を書き出す例
select * from app.v_antique_ledger
where 取引年月日 between '2026-01-01' and '2026-12-31'
order by 取引年月日;
```

## 不正品の申告

盗品の疑いがある場合の警察への申告義務（法第15条第3項）に備えて、
`memo` と `item_comments` に気づいた点を残せるようにしています。
納品担当者が検品で違和感に気づいたら、その場でコメントを残せます。
