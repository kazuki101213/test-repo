# 06 アプリの公開（Vercel）

2 つのアプリを、それぞれ別の URL で開けるようにします。

**大元アプリと納品アプリは、必ず別プロジェクトとして作ってください。**
URL が分かれていれば、外注先には納品アプリの URL だけを渡せます。

## 用意するもの

- Supabase の **Project URL**（`https://xxxx.supabase.co`）
- Supabase の **anon / publishable key**

この 2 つは公開されても問題ありません。データを守っているのは RLS です。

## 手順（大元アプリ）

1. https://vercel.com を開いて **Continue with GitHub** でログイン
2. **Add New → Project**
3. `test-repo` を選んで **Import**
4. 設定を次のようにする

   | 項目 | 値 |
   |---|---|
   | Project Name | `bussan-admin` |
   | Framework Preset | Vite（自動で選ばれます） |
   | **Root Directory** | **`apps/admin`** ← Edit を押して選ぶ |

5. **Environment Variables** を 2 つ足す

   | Name | Value |
   |---|---|
   | `VITE_SUPABASE_URL` | Supabase の Project URL |
   | `VITE_SUPABASE_ANON_KEY` | anon / publishable key |

6. **Deploy** を押す（2〜3 分）

## 手順（納品アプリ）

同じ手順をもう一度、次の 2 か所だけ変えて行います。

| 項目 | 値 |
|---|---|
| Project Name | `bussan-delivery` |
| **Root Directory** | **`apps/delivery`** |

環境変数は大元アプリと同じ 2 つです。

## ブランチについて

作業ブランチは `claude/merchandise-management-system-6jpocg` です。
Pull Request をマージする前は、Vercel の
`Settings → Git → Production Branch` をこのブランチ名にしてください。
マージ後は `main` に戻します。

## Supabase 側の設定

`Authentication → URL Configuration` を開いて、

- **Site URL**: 大元アプリの URL
- **Redirect URLs**: 両アプリの URL を追加

メールアドレスとパスワードでログインするだけなら未設定でも動きますが、
パスワード再設定メールを使うなら必要です。

## 動作確認

1. 大元アプリの URL を開く
2. `app.link_login` で紐付けたメールアドレスとパスワードでログイン
3. ダッシュボードに現在庫数と今月の数字が出れば成功

納品アプリは、納品担当者のアカウントを作って紐付けてから確認します。
管理者アカウントで納品アプリを開いても、担当している商品が無いので一覧は空です。

## 担当者を増やす

1. Supabase の `Authentication → Users → Add user`（**Auto Confirm User** をオンに）
2. SQL Editor で紐付ける

```sql
select app.link_login('kubota@example.com', 'DD');
select * from app.v_logins;   -- 誰がログインできるか確認
```

担当者コードは [03 セットアップ](03-セットアップ.md) の表を見てください。

## スマホで使う

納品アプリはスマホ前提の作りです。ブラウザで URL を開いて
「ホーム画面に追加」しておくと、アプリのように起動できます。

## 直したいところが出たら

コードを直して push すれば、Vercel が自動で作り直します。
本番に出す前に確認したい場合は、Pull Request を作ると
Vercel がプレビュー用の URL を用意します。
