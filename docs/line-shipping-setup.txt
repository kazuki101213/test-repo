LINE発送依頼連携：設定手順と現在の範囲

1. https://www.lycbiz.com/jp/service/line-official-account/account/ から公式アカウントを作成。
2. WEB版LINE Official Account Manager → 設定 → Messaging API → 利用する。
   プロバイダーは運用する会社/本人名で選択する。後から変更できない。
3. LINE Developers → 対象Messaging APIチャネル。
   基本設定のチャネルシークレット、Messaging API設定のチャネルアクセストークンを確認/発行。
4. Supabase → Edge Functions → Secretsへ次を保存。キーをチャットやGitに貼らない。
   LINE_CHANNEL_SECRET
   LINE_CHANNEL_ACCESS_TOKEN
   LINE_OFFICIAL_ACCOUNT_URL は任意。未設定の場合はLINE公式APIで確認したbasicIdから友だち追加URLを作成。
5. 登録機能の本番反映後、Webhook URLを次へ設定し「検証」、Webhookの利用をON。
   https://xgoppuqoqeppckyunnvx.supabase.co/functions/v1/delivery-line/webhook
   署名検証はEdge Function内で実行。チャネルアクセストークンをURLに入れない。
6. 納品担当者が納品アプリに本人としてログイン → 通知設定 → LINE通知。
   友だち追加 → 連携コードを発行 → 表示文を公式アカウントの1対1トークへ送信。
   「登録状況を確認」で登録済みになることを確認。コードは10分有効、1回限り。

自動発送依頼
Chromeの専用4時間タイマーで、既存の購入・落札確認後に処理する。他の毎分タイマーと1時の処理は維持。
LINEの恒常的な毎分Cronは廃止し、写真とコードが揃ったイベント時に送信する。失敗時だけ期限付きで再試行。
新規依頼のみが対象。既存の発送依頼を一斉に再送しない。担当者は本人でLINE連携する。
商品写真の全体・型番確認をアプリで一度指定する。既存の商品写真を再利用し、写真のコピーを増やさない。
配送サイズ未設定の場合は本文・全体写真・型番確認写真を送り、コードは取得しない。アプリに設定不足の理由は表示しない。
モニターは140、ブルーレイレコーダーは100を型番分類から使用する。
小物はその商品の指定サイズを優先し、未指定なら同じASIN（無い場合はメーカー+型番）の実発送サイズを利用する。汎用名だけでは引き継がない。
サイズが決まれば保存された配送方法・発送場所で現在取引のコードを取得し、3枚目に付ける。
取得失敗や結果不明を「サイズ未設定」の例外に置き換えない。古い取引のコードを送らない。
同じ発送依頼のLINE再送を防ぐ。あとからコードを取得しても同じ依頼を自動で再通知しない。
発送・発送コード表示ボタンは残す。実際の発送通知は従来の受付確認条件と1時処理のまま。
DBのenabledは配布・検証後に有効化する。実送信を含む検証結果は作業記録に別記する。
