# LINE発送依頼の写真選択

商品写真とLINE用写真は従来別管理で、通知写真の手動保存だけがLINE設定を作成していた。このため、出品写真があってもLINE設定が作られず、定期発送依頼で写真未選択が発生していた。

現在は商品写真の追加・削除・差し替え、出品情報の登録で、自動判定を準備する。既存のLINE配信処理が保存済みの選択を優先して利用し、設定がなければ画像の内容から全体写真・型番写真を選んで保存する。以前の送信待ち商品も配信時に対象へ加える。既存の配信cronを再利用し、新しい巡回タイマーは作らない。

1. 対象商品のアプリ内の商品写真を優先する。梱包写真・別商品の写真は対象外。
2. アプリ内に商品写真がない場合だけ、同商品に紐づく現在のメルカリ・ヤフオク出品ページの商品写真を取得する。おすすめ商品の画像は使用しない。選択した写真を対象商品の非公開Storageへ保存する。
3. 画像とカタログ型番だけを既存のGemini接続へ送る。SKU・担当者・配送先・取引情報は送らない。返却値は候補内の写真番号と確信度のみ。判定結果は対象商品のLINE設定へ保存する。
4. 型番を読み取れない場合は型番写真を捏造しない。全体写真だけ保存し、写真追加時に再判定する。一時的な取得・API失敗は15分後に再試行し、同じ変更について最大3回に制限する。
5. 手動選択、配送設定、送信済み履歴は上書きしない。処理中に写真が増減した場合は結果を破棄して再判定する。失敗しても既存の写真・商品リンクによるLINE送信は継続する。写真設定だけの操作ではLINEを送らない。

判定は1呼出につき1商品、最大20枚、1枚4MiB・合計16MiB。画像取得元はアプリの非公開Storageか、正確な出品IDに紐づく許可済み配信元に限定する。ページが取得制限されている場合や型番写真そのものがない場合、正しい型番写真の保存までは保証できない。

内部の準備・保存RPCと診断用`select-line-photos`はサービス専用。通常利用者へ権限を開放しない。意図的なLINE再送は従来どおり本人・担当者権限、現在の未発送取引、現担当者へのLINE連携、送信済み依頼、重複防止の確認を通す。
