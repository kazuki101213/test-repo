# 04 移行手順

既存のスプレッドシートを Supabase に取り込みます。
**まず `--dry-run` で確認してから本番に流してください。**

## 1. CSV を書き出す

Google スプレッドシートで **ファイル → ダウンロード → カンマ区切り形式(.csv)**。
シートごとに 1 ファイルになります。

```
data/
├── products.csv          総合管理表 →「商品リスト」シート
└── items/
    ├── kubota.csv        納品管理表 → 久保田ゆかり のシート
    ├── shinkawa.csv      納品管理表 → 新川水紀 のシート
    ├── koeru.csv         …担当者シートをすべて
    └── ...
```

`data/` は `.gitignore` 済みです（仕入金額が入るのでコミットしないこと）。

## 2. 下見する

```bash
node scripts/import-sheets.mjs \
  --products data/products.csv \
  --items 'data/items/*.csv' \
  --dry-run
```

件数、1 行目の変換結果、要確認の警告が出ます。よく出る警告と対処:

| 警告 | 対処 |
|---|---|
| `仕入担当者「○○」が staff に未登録` | `app.staff` に追加するか、シート側の表記ゆれを直す |
| `SKU 重複のためとばしました` | シートをまたいで同じ SKU がある。どちらが正しいか確認する |
| `購入日が読めないためとばしました` | 空行か日付欄の書式崩れ。シートを直す |
| `ASIN が読めない行をとばしました` | 商品リスト側の ASIN 欄を確認 |

## 3. 取り込む

```bash
export SUPABASE_URL='https://xxxx.supabase.co'
export SUPABASE_SERVICE_ROLE_KEY='eyJ...'

node scripts/import-sheets.mjs \
  --products data/products.csv \
  --items 'data/items/*.csv'
```

- `products` は ASIN、`items` は SKU で **upsert** します。何度流しても増えません。
- 既存の SKU はそのまま使い、再発番しません。
- `service_role` キーは RLS を無視します。ローカルの端末でのみ実行してください。

## 4. 取り込み後に確認すること

```sql
-- 件数（総合管理表の KPI と突き合わせる）
select count(*) from app.items;
select count(*) from app.items where status not in ('販売済','返品','廃棄');

-- 担当者が付かなかった行
select sku, title from app.items where deliverer_id is null;

-- 商品マスタに結びつかなかった行（ASIN 違い / マスタ未登録）
select sku, asin, title from app.items where product_id is null and asin is not null;

-- 年をまたぐ日付が怪しい行（出荷日が購入日より前）
select sku, purchased_at, shipped_on from app.items where shipped_on < purchased_at;
```

最後の 1 つは、シートで `12/28` のように年を省略した行が
購入日の年で補完された結果です。大元アプリの在庫一覧から直してください。

## 5. 販売実績について

納品管理表には販売日・販売価格の列がありません（Amazon 側が持っています）。
そのため移行直後は `sold_on` が空で、月次集計の売上は 0 になります。

埋め方は 2 通りあります。

1. **これから分だけ入れる** — 大元アプリの在庫一覧から「販売登録」で 1 件ずつ。
   売れるたびに入れれば数日で実態に追いつきます。
2. **過去分も入れる** — Amazon セラーセントラルの
   「レポート → ペイメント → トランザクション」を CSV で落とし、
   SKU をキーに `sold_on` / `sold_price` / `payout_amount` を UPDATE します。

```sql
-- 例: 一時テーブルに読み込んでから突き合わせる
update app.items i
   set sold_on = t.sold_on, sold_price = t.price, payout_amount = t.payout
  from tmp_amazon_settlement t
 where t.sku = i.sku;
```

## 6. 切り替え

しばらくはスプレッドシートと両方に入れて、数字が合うことを確認してください。
合ったらスプレッドシートは**書き込み禁止にして残す**のが安全です
（古物台帳は最終取引から 3 年間の保存義務があります）。
