# 04 移行手順

スプレッドシートの中身を Supabase に移します。
**パソコンへのインストールは不要で、ダッシュボードの操作だけで終わります。**

## 全体の流れ

```
  スプレッドシート            このリポジトリ              Supabase
  ───────────────            ──────────────              ────────
  .xlsx で書き出し  ──▶  sheets-to-csv.py      ①受け皿を作る SQL を貼る
                          import-sheets.mjs ──▶ ②CSV を 2 つアップロード
                                                ③本番へ移す SQL を貼る
```

取り込みファイル一式（①②③）はこちらで作ってお渡しします。
自分で作り直したい場合は「ファイルを自分で作る」を見てください。

## 取り込み（ダッシュボードだけで完結）

### ① 受け皿を作る

1. Supabase の左メニュー **SQL Editor** を開く
2. `01-受け皿を作る.sql` の中身を貼り付けて **Run**

CSV を受け止めるための、一時的な空テーブルが 2 つできます。

### ② CSV をアップロードする

1. 左メニュー **Table Editor** を開く
2. 左上のスキーマ切り替えを **`public` から `app` に変える**
3. `staging_products` を選ぶ → **Insert → Import data from CSV** → `products.csv`
4. `staging_items` を選ぶ → 同じ手順で `items.csv`

数千行あるので、`items.csv` は少し時間がかかります。

### ③ 本番のテーブルへ移す

1. **SQL Editor** に戻る
2. `03-本番へ移す.sql` を貼り付けて **Run**

最後に件数が表示されます。受け皿テーブルはここで自動的に消えます。

## 取り込み後の確認

SQL Editor で実行してください。

```sql
-- 件数
select count(*) from app.items;                              -- 3,160 前後
select count(*) from app.items where sold_on is not null;     -- 2,544 前後
select count(*) from app.products;                            -- 630

-- 月次（スプレッドシートの集計と突き合わせる）
select month, 仕入数, 仕入金額, 販売数, 売上, 粗利益
from app.v_monthly_summary order by month desc limit 6;

-- 古物台帳として記載が足りない行
select 不備, count(*) from app.v_ledger_gaps group by 不備 order by 2 desc;

-- 取り込めなかった行（元データで SKU が重複していたもの）
select sku, reason from app.import_conflicts;
```

## 移行元スプレッドシートとの突き合わせ結果

実データで検証したときの数字です。

| 項目 | スプレッドシート | 取り込み | 差 |
|---|---:|---:|---|
| 総仕入れ数 | 3,035 | 3,035 | **一致** |
| 返品処理 | 82 | 82 | **一致** |
| Amazon返品 | 123 | 123 | **一致** |
| 9月売上 | ¥1,598,879 | ¥1,598,879 | **一致** |
| 9月粗利益 | ¥378,138 | ¥378,138 | **一致** |
| 総販売数 | 2,542 | 2,544 | +2 |
| 売上高 | ¥44,533,899 | ¥44,483,519 | −¥50,380（0.11%） |
| 商品リスト | 628 | 630 | +2 |

差が残っている 3 項目は、スプレッドシート側の集計セルが
どの行を数えているかによるものと見ています。取り込んだ明細そのものは
1 行ずつ元データから作っているので、必要なら SQL で内訳を確認できます。

## 元データにもともと欠けているもの

移行で作り出すことはせず、欠けたまま取り込んで一覧できるようにしています。

| 内容 | 件数 | どうなるか |
|---|---:|---|
| 購入日が空（SKU が `18991230`） | 54 | `v_ledger_gaps` に「取引年月日が未記入」として出る |
| 仕入担当者が空 | 127 | 付属品の単独手配や Amazon 返品の再処理。SKU も 2 文字形式 |
| 1万円以上で相手方の住所が空 | 多数 | `v_ledger_gaps` に出る（[05 古物台帳](05-古物台帳.md) 参照）|
| SKU の重複 | 3 | `app.import_conflicts` に退避。大元アプリで振り直す |
| 販売日はあるが注文価格が空 | 2 | 販売情報を保留にして取り込み（金額を入れれば販売済みになる）|

Amazon 返品の 45 件は元シートに日付が一切ないため、
返品日は入れずに「Amazon返品」の印だけを残しています。

## ファイルを自分で作る

```bash
# 1) スプレッドシートを .xlsx で書き出す
#    Google スプレッドシート → ファイル → ダウンロード → Microsoft Excel (.xlsx)
#    ※ CSV で落とすと先頭シートしか取れないので .xlsx にすること

# 2) シートごとの CSV にする
pip install openpyxl
python3 scripts/sheets-to-csv.py 総合管理表.xlsx 納品管理表.xlsx --out data

# 3) 中身を確認する（書き込みなし）
node scripts/import-sheets.mjs \
  --ledger 'data/総合管理表/仕入れ販売管理.csv' \
  --products 'data/総合管理表/商品リスト.csv' \
  --accessories 'data/納品管理表/*.csv' \
  --dry-run

# 4) 取り込みファイル一式を作る
node scripts/import-sheets.mjs ... --bundle data/取り込み
```

`data/` は `.gitignore` 済みです。仕入金額や利益が入るのでコミットしないでください。

主な材料は **総合管理表の「仕入れ販売管理」シート**です。
仕入れから販売・返金まで揃っているのはここだけで、納品管理表の担当者シートからは
「付属品」列だけを SKU で突き合わせて補っています。

## これから売れた分をどう入れるか

移行後は大元アプリの在庫一覧から「販売登録」で 1 件ずつ入れられます。
まとめて入れたい場合は、Amazon セラーセントラルの
「レポート → ペイメント → トランザクション」の CSV を SKU で突き合わせて
`sold_on` / `sold_price` / `payout_amount` を更新してください。

## 切り替え

しばらくはスプレッドシートと両方に入力して、数字が合うことを確認してください。
合ったらスプレッドシートは**書き込み禁止にして残す**のが安全です
（古物台帳は最終取引から 3 年間の保存義務があります）。
