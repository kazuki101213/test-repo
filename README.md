# 物販管理システム

Amazon・メルカリでの物販を、スプレッドシートから **Supabase + 2 つのアプリ** に移すためのリポジトリです。

現在の「総合管理表」「納品管理表」で回している業務を、次のように置き換えます。

| 今 | これから |
|---|---|
| 総合管理表（KPI・商品リスト・経費） | **大元アプリ**（`apps/admin`） |
| 納品管理表（担当者ごとにシートを分けて共有） | **納品アプリ**（`apps/delivery`） |
| シート間を SKU とコピペでつないでいた | **Supabase の 1 テーブル**を両アプリが見る |
| 古物台帳を兼ねた手作業の記録 | **古物台帳ビュー**（CSV 出力可・変更履歴つき） |

## 2 つのアプリを分ける理由

納品担当者には外注先（株式会社コエル、株式会社吉光など）も含まれます。
仕入金額・利益・他の担当者の作業・経費は見せたくない一方で、
自分の担当分はスマホからすぐ更新できる必要があります。

そこで **データは 1 つ、入口は 2 つ** にしました。

```
                    ┌─────────────────────────┐
  大元アプリ ──────▶│  Supabase (PostgreSQL)  │◀────── 納品アプリ
  管理者 / 仕入担当  │                         │        納品担当者
  ・全件の閲覧と編集 │   app.items             │        ・自分の担当分だけ
  ・仕入登録(SKU発番)│   ← SKU が唯一の連携キー │        ・作業チェックと写真
  ・販売登録 / 経費  │   RLS で行を出し分け     │        ・コメント
  ・古物台帳         └─────────────────────────┘
```

納品担当者は `app.items` を直接 UPDATE できません（RLS でブロック）。
更新は `app.set_work_progress()` などの RPC 経由に限定してあり、
**触れる列そのものを DB 側で固定**しています。アプリを改造されても抜けません。

## SKU がアプリ間の共通言語

現行のスプレッドシートの SKU をそのまま引き継ぎます。

```
2340-EEMM-20260916-1296
 │    │ │      │       └─ 仕入金額 ÷ 10（¥12,961）
 │    │ │      └───────── 購入日 2026-09-16
 │    │ └──────────────── 納品担当者コード（MM = 株式会社吉光）
 │    └────────────────── 仕入担当者コード（EE = 石川秀樹）
 └─────────────────────── 通番号（本体と買い足した付属品が共有する）
```

- 大元アプリで仕入登録すると DB が自動で発番します（`app.build_sku`）。
- 納品アプリは SKU 検索・スキャンで同じ商品を引けます（`app.find_by_sku`）。
- 一度 Amazon に登録した SKU は変更しません。担当者を替えても SKU は据え置きです。

## 構成

```
supabase/migrations/   スキーマ・RLS・ビュー（これが仕様の本体）
supabase/tests/        ローカル PostgreSQL での検証スクリプト
packages/shared/       両アプリが共有する型・SKU ロジック・Supabase クライアント
apps/admin/            大元アプリ（React + Vite）
apps/delivery/         納品アプリ（React + Vite / スマホ前提）
scripts/import-sheets.mjs  スプレッドシート CSV → Supabase の移行スクリプト
docs/                  設計と手順
```

## はじめかた

> 初めての方は **[docs/00-はじめに.md](docs/00-はじめに.md)** から読んでください。
> 用語を使わずに、何を押せばいいかだけを書いてあります。

```bash
pnpm install

# 1) Supabase プロジェクトを作り、マイグレーションを流す
supabase link --project-ref <your-project-ref>
supabase db push

# 2) 環境変数
cp .env.example apps/admin/.env.local
cp .env.example apps/delivery/.env.local   # URL と anon key を書き込む

# 3) 起動
pnpm dev:admin      # http://localhost:5173
pnpm dev:delivery   # http://localhost:5174
```

詳しい手順は [`docs/03-セットアップ.md`](docs/03-セットアップ.md)、
スプレッドシートからの移行は [`docs/04-移行手順.md`](docs/04-移行手順.md) を見てください。

## 検証

Supabase CLI がなくても、ローカルの PostgreSQL 16 でスキーマと RLS を検証できます。

```bash
sudo service postgresql start
supabase/tests/run.sh      # SKU 発番・RLS・古物台帳・集計をまとめて確認
pnpm -r typecheck
```
